**Intro**

The CLI (Command-Line Interface, also called “terminal” or “shell”) is a text-based user interface used to view, manage, and interact with the computer by typing specific commands. CLI AI Agents are the latest step in the evolution of developer tools. They combine the power of LLMs with direct access to a computer’s terminal, files, and external tools. Just imagine using the smartest AI models directly on your terminal, without needing a web interface.
CLI（命令行界面，也称为“终端”或“shell”）是一种基于文本的用户界面，用于通过输入特定命令来查看、管理和与计算机交互。CLI AI 智能体是开发者工具演进的最新一步。它们将大语言模型（LLM）的能力与对计算机终端、文件和外部工具的直接访问相结合。试想一下，直接在终端中使用最智能的 AI 模型，而无需任何网页界面。

In 2023, the tech world had a major breakthrough with the tool calling function introduced by OpenAI. Instead of only producing text, models could also perform actions by sending structured requests to applications, getting an output, and continuing reasoning.
2022 年 ChatGPT 的发布改变了人们与软件交互的方式，用户可以使用自然语言而非输入命令。2023 年，随着 OpenAI 引入函数调用（Tool Calling）功能，科技界取得了重大突破。模型不再仅仅生成文本，还可以通过向应用程序发送结构化请求、获取输出并继续推理来执行操作。

Finally, in 2025, Super CLI arrived, the first AI Agent explicitly built for running on your CLI without a web interface. Anthropic’s Claude Code and OpenAI’s Codex CLI followed right after. The CLI has evolved from a place where humans executed commands into a collaborative workspace where users define goals, and AI carries out much of the execution.
最终，2025 年 Super CLI 面世，这是第一个明确为在 CLI 上运行而构建且无需网页界面的 AI 智能体。Anthropic 的 Claude Code 和 OpenAI 的 Codex CLI 紧随其后。CLI 智能体之所以成功，是因为它们自然地融入了现有的开发者工作流。它们没有取代终端，而是通过推理增强了终端的功能。CLI 已经从人类执行命令的地方演变为一个协作工作空间，用户定义目标，而 AI 则负责大部分执行工作。

Today, there are three types of CLI Agents:
如今，CLI 智能体主要分为三类：

**Setup**
**设置**

Let’s start by setting up Ollama (pip install ollama==0.6.2), the most famous library to run open-source LLMs locally. First of all, you need to download Ollama from the website. Then, on your CLI, use the command to download the selected LLM. I’m going with Alibaba’s Qwen as it’s both smart and light. After the download is completed, you can move on to Python and start writing code.
让我们从设置 Ollama（pip install ollama==0.6.2）开始，这是运行本地开源 LLM 最著名的库。首先，你需要从官网下载 Ollama。然后，在 CLI 中使用命令下载选定的 LLM。我选择阿里巴巴的 Qwen，因为它既智能又轻量。下载完成后，你就可以开始编写 Python 代码了。

```python
import ollama
llm = "qwen2.5"
```

This Agent must be able to execute shell commands on the CLI, so we need to provide it with the appropriate Tool. First, we define the function that actually performs the action, then it must be mapped to Ollama schemas for tool calling. For the CLI commands, we are going to need the subprocess module, a built-in library used to run system commands directly from your Python code.
该智能体必须能够在 CLI 上执行 shell 命令，因此我们需要为其提供适当的工具。首先，我们定义实际执行操作的函数，然后将其映射到 Ollama 的工具调用模式（schema）中。对于 CLI 命令，我们需要使用 `subprocess` 模块，这是一个内置库，用于直接从 Python 代码中运行系统命令。

```python
import subprocess

# 1. Define the actual tool function
# 1. 定义实际的工具函数
def execute_shell_command(command: str) -> str:
    """Executes a terminal command and returns stdout or stderr."""
    """执行终端命令并返回标准输出或标准错误。"""
    try:
        result = subprocess.run(command, shell=True, capture_output=True, text=True, timeout=10)
        return result.stdout if result.returncode == 0 else result.stderr
    except Exception as e:
        return str(e)

# 2. Map tool names to Python functions
# 2. 将工具名称映射到 Python 函数
TOOL_MAP = {
    'execute_shell_command': execute_shell_command
}

# 3. Provide schema representations for Ollama
# 3. 为 Ollama 提供模式表示
TOOLS_SCHEMA = [
    {
        'type': 'function',
        'function': {
            'name': 'execute_shell_command',
            'description': 'Execute safe terminal shell commands on the local machine.',
            'parameters': {
                'type': 'object',
                'properties': {
                    'command': {
                        'type': 'string',
                        'description': 'The exact bash or shell command to run.',
                    }
                },
                'required': ['command'],
            },
        },
    }
]
```

**Agent**
**智能体**

In the interaction with a LLM chatbot, there are 3 types of roles:
在与 LLM 聊天机器人的交互中，有三种角色：

*   “role”:“system” — used to pass core instructions to the model on how the conversation should proceed
*   “role”:“system” — 用于向模型传递关于对话应如何进行的核心指令
*   “role”:“user”— used for user’s questions
*   “role”:“user” — 用于用户的提问
*   “role”:“assistant” — it’s the reply from the model
*   “role”:“assistant” — 模型的回复

When we give the very first instruction to the model, we have to specify that it’s the system prompt.
当我们向模型发出第一条指令时，必须指定它是系统提示词（system prompt）。

```python
messages = [
    {"role": "system", "content": "You are a helpful local CLI assistant. You can inspect the system and run tasks using your tools."}
]
```

In order to keep the chat with the AI alive, I will use a loop that starts with the user’s input, and then invokes the Agent to respond (which can be a text from the LLM or the activation of a Tool).
为了保持与 AI 的对话，我将使用一个循环，从用户输入开始，然后调用智能体进行响应（这可能是来自 LLM 的文本，也可能是工具的激活）。

```python
import sys

while True:
    try:
        user_input = input("🙂 >")
        if user_input.lower() in ['exit', 'quit']:
            break
        if not user_input.strip():
            continue
        
        messages.append({"role": "user", "content": user_input})
        
        # Request completion from Ollama with enabled tools
        # 请求 Ollama 完成任务并启用工具
        response = ollama.chat(
            model=llm,
            messages=messages,
            tools=TOOLS_SCHEMA
        )
        
        ### WE WILL ADD CODE HERE ###
        ### 我们将在此处添加代码 ###
        
    except KeyboardInterrupt:
        print("\nExiting.")
        sys.exit(0)
```

If the model wants to use the Tool, the appropriate function needs to be executed with the input parameters suggested by the LLM in its response object.
如果模型想要使用工具，则需要使用 LLM 在其响应对象中建议的输入参数来执行相应的函数。

```python
import json

# Process potential tool calls requested by the model
# 处理模型请求的潜在工具调用
while response.get('message', {}).get('tool_calls'):
    messages.append(response['message'])
    for tool_call in response['message']['tool_calls']:
        tool_name = tool_call['function']['name']
        arguments = tool_call['function']['arguments']
        print(f"🔧 >[Executing Tool] {tool_name}({json.dumps(arguments)})")
        
        if tool_name in TOOL_MAP:
            # Execute tool and grab output string
            # 执行工具并获取输出字符串
            tool_result = TOOL_MAP[tool_name](**arguments)
            
            # Provide tool outcome back to the model context
            # 将工具结果反馈给模型上下文
            messages.append({
                "role": "tool",
                "name": tool_name,
                "content": tool_result
            })
        else:
            print(f"⚠️ >Unknown tool execution attempted: {tool_name}")
            
    # Re-submit history including tool logs for final evaluation
    # 重新提交包含工具日志的历史记录以进行最终评估
    response = ollama.chat(
        model=llm,
        messages=messages,
        tools=TOOLS_SCHEMA
    )
```

Since the CLI is a delicate tool, in the last lines of code, I asked the model to double check the conversation history and action parameters.
由于 CLI 是一个敏感工具，在最后几行代码中，我要求模型仔细检查对话历史和操作参数。
