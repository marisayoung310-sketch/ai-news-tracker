# Topology-Aware Data Movement for Disaggregated GPU Inference
# 面向存算分离 GPU 推理的拓扑感知数据传输技术

**Abstract:** Disaggregated LLM inference creates a datacenter networking problem that no existing system solves correctly. When prefill and decode run on separate GPU pools, the KV cache must be transferred between them. For a 70B model this is 2.6 GB per request, exceeding 100 GB/s aggregate at production scale. Yet DistServe, Splitwise, and Mooncake all use uniform RDMA, ignoring that bandwidth between two GPUs varies by 72x depending on their physical relationship: 900 GB/s via NVLink within a domain, 50 GB/s via InfiniBand across nodes, 12.5 GB/s via TCP across data centers.

**摘要：** 存算分离（Disaggregated）的大模型推理带来了一个目前尚无系统能妥善解决的数据中心网络问题。当预填充（prefill）和解码（decode）任务在不同的 GPU 池上运行时，KV 缓存必须在两者之间进行传输。对于一个 70B 参数的模型，每个请求需要传输 2.6 GB 数据，在生产规模下总带宽需求超过 100 GB/s。然而，DistServe、Splitwise 和 Mooncake 等现有系统均采用统一的 RDMA 传输，忽略了两个 GPU 之间的带宽会因物理连接方式的不同而产生高达 72 倍的差异：域内通过 NVLink 可达 900 GB/s，跨节点通过 InfiniBand 为 50 GB/s，而跨数据中心通过 TCP 仅为 12.5 GB/s。

We design a topology-aware transfer orchestrator that discovers interconnect hierarchy at startup and selects optimal transport per transfer. Three mechanisms work together: (1) pipelined layer-by-layer transfer that overlaps transmission with ongoing prefill, hiding 60 to 85 percent of latency behind computation; (2) NVLink domain-aware placement for Mixture-of-Experts models that co-optimizes expert dispatch with KV cache locality; and (3) CXL 3.0 memory expanders as a shared overflow tier providing 6x capacity at 86x lower latency than NVMe.

我们设计了一种拓扑感知传输编排器，它能在启动时发现互连层级，并为每次传输选择最优的传输路径。该方案通过三种机制协同工作：(1) 流水线式的逐层传输，将传输过程与正在进行的预填充计算重叠，从而将 60% 到 85% 的传输延迟隐藏在计算过程中；(2) 针对混合专家模型（MoE）的 NVLink 域感知放置策略，协同优化专家调度与 KV 缓存的局部性；(3) 利用 CXL 3.0 内存扩展器作为共享溢出层，相比 NVMe 提供 6 倍的容量，同时延迟降低 86 倍。

Full evaluation requires multi-node clusters with heterogeneous interconnects and CXL 3.0 hardware that is beyond academic resources and not yet available in GPU clouds. We present analytical bandwidth models, component implementations, and projected analysis across three architectures showing 3 to 18x transfer latency reduction over uniform RDMA.

完整的评估需要具备异构互连和 CXL 3.0 硬件的多节点集群，这超出了学术界的资源范畴，且目前在 GPU 云服务中尚不可用。我们提出了分析性带宽模型、组件实现方案，并对三种架构进行了预测性分析，结果显示该方案相比统一的 RDMA 传输，可将传输延迟降低 3 到 18 倍。
