# Should AI Developers Make the Switch from Polars to Pandas?
# AI 开发者应该从 Pandas 转向 Polars 吗？

If you are someone who has used Python for data analysis (or dealt with data in any form) for even a few weeks, you have almost certainly used Pandas, or at least heard of it. For more than ten years, Pandas has been the standard library for cleaning data, exploring datasets, and preparing said data for machine learning algorithms. Whether you did that in the context of a university course, a side project, or a full-time job, Pandas has become nearly synonymous with data analysis in Python.

如果你曾使用 Python 进行数据分析（或以任何形式处理过数据），哪怕只有几周时间，你也几乎肯定使用过 Pandas，或者至少听说过它。十多年来，Pandas 一直是用于清洗数据、探索数据集以及为机器学习算法准备数据的标准库。无论你是在大学课程、个人项目还是全职工作中接触它，Pandas 在 Python 数据分析领域几乎已经成为了代名词。

But in recent years, a competitive alternative to Pandas has entered the scene, a library whose name has become more and more frequent in tutorials, GitHub projects, and AI workflows. That library is Polars. Many developers have adopted Polars as a faster option than Pandas. They used different benchmarks to show good speed boosts, especially when dealing with large datasets. Considering this speed, you might be wondering: If Polars is so much faster, then why isn’t it being used by everybody?

但近年来，一个 Pandas 的竞争对手出现在了舞台上，这个库的名字在教程、GitHub 项目和 AI 工作流中出现的频率越来越高。这个库就是 Polars。许多开发者已经采用 Polars 作为比 Pandas 更快的替代方案。他们通过不同的基准测试展示了显著的速度提升，尤其是在处理大型数据集时。考虑到这种速度优势，你可能会问：如果 Polars 快这么多，为什么大家不都用它呢？

The response is more interesting when we look beyond the advantage of speed. See, Pandas and Polars were based on different philosophies, and it is much more valuable to understand those philosophies than to make a decision based on benchmark figures. So, in this article we will look at the differences between the two libraries, explain why Polars is usually faster (keyword here: is usually), and show when one library is the better option.

当我们跳出速度优势去看待这个问题时，答案会更有趣。Pandas 和 Polars 基于不同的哲学理念，理解这些理念比单纯根据基准测试数据做决定更有价值。因此，在本文中，我们将探讨这两个库之间的差异，解释为什么 Polars 通常更快（关键词：通常），并说明在什么情况下选择其中一个库会更好。

### Why Was Polars Created?
### 为什么会诞生 Polars？

When Pandas was first launched in 2008, computers were different; most personal computers had only a small number of CPU cores, the datasets were much smaller, and memory was usually the limiting factor. So, Pandas was designed with these realities in mind. The API focused on simplicity and readability, allowing users to perform intuitive operations when working with tabular data. Nevertheless, when dataset sizes reached millions of rows, some of Pandas’ original design choices became its limitations.

当 Pandas 在 2008 年首次发布时，计算机的情况与现在不同；大多数个人电脑只有少量的 CPU 核心，数据集规模小得多，内存通常是限制因素。因此，Pandas 的设计考虑了这些现实。其 API 专注于简洁性和可读性，使用户在处理表格数据时能够进行直观的操作。然而，当数据集规模达到数百万行时，Pandas 最初的一些设计选择反而成了它的局限。

Today, modern processors have many CPU cores. But traditional Pandas operations normally run on a single core. Moreover, recent programming languages, for example Rust, have made it possible to create faster, safer, and more parallel data-processing libraries. Polars was designed to take advantage of this new hardware landscape. Rather than trying to replace Pandas feature for feature, it was designed around the idea that modern hardware needs modern software.

如今，现代处理器拥有多个 CPU 核心，但传统的 Pandas 操作通常只在单核上运行。此外，像 Rust 这样的现代编程语言使得创建更快、更安全、更具并行性的数据处理库成为可能。Polars 的设计初衷就是为了利用这种新的硬件环境。它并没有试图在功能上一一取代 Pandas，而是围绕“现代硬件需要现代软件”这一理念进行设计。

### At First Glance, They Look Similar
### 初看之下，它们很相似

One reason Polars has become so popular is that its grammar feels familiar. For example, loading a CSV file, selecting certain columns, and filtering out certain rows is very similar. The amount of effort needed to switch between the two libraries when carrying out simple operations is surprisingly small. The actual differences can only be seen if you look below the surface.

Polars 之所以如此受欢迎，原因之一是它的语法让人感到亲切。例如，加载 CSV 文件、选择特定列以及过滤特定行的方式非常相似。在执行简单操作时，在两个库之间切换所需的成本出奇地低。只有深入底层，才能看到它们真正的区别。

People often think that Polars is faster since it was written in Rust. Although Rust does contribute to its performance, it by no means tell the entire story. The reason Polars is fast is due to several architectural choices that combine in order to enhance performance; two important features (in my opinion):

人们常认为 Polars 快是因为它是用 Rust 编写的。虽然 Rust 确实对性能有所贡献，但这绝不是全部原因。Polars 之所以快，是因为它结合了多种架构选择来提升性能；在我看来，其中两个重要特性是：

1. **Parallel Execution (并行执行):** Polars, unlike Pandas, automatically spreads out many operations over several CPU cores. So, if you are sorting a dataset that has, say, a million rows, rather than having a single worker sort the whole dataset, Polars divides the task among a number of workers who then work at the same time.
   **并行执行：** 与 Pandas 不同，Polars 会自动将许多操作分配到多个 CPU 核心上。因此，如果你要对一个拥有百万行的数据集进行排序，Polars 不会让单个工作线程处理整个数据集，而是将任务拆分给多个工作线程同时进行。

2. **Lazy Execution (惰性执行):** One of the most innovative features of Polars is its lazy execution. Normally, each line of code is carried out right away. Every operation produces intermediate results. Polars does it differently! Instead of performing each command at once, it creates a query plan that describes all the things you want to achieve. Only when you request the final result does Polars optimize the entire workflow. Everything before the `.collect()` simply describes the computation, and only then does Polars execute the optimized plan. This approach enables Polars to remove unnecessary work before accessing the data.
   **惰性执行：** Polars 最具创新性的特性之一是其惰性执行。通常情况下，每一行代码都会立即执行，且每个操作都会产生中间结果。Polars 的做法则不同！它不会立即执行每条命令，而是创建一个描述你想要实现的所有目标的查询计划。只有当你请求最终结果时，Polars 才会优化整个工作流。在 `.collect()` 之前的一切都只是在描述计算过程，只有在那之后，Polars 才会执行优化后的计划。这种方法使 Polars 能够在访问数据之前剔除不必要的工作。

### Memory Matters Too
### 内存同样重要

Performance is not solely a matter of CPU speed. We also need to consider the time needed to move data through the memory, which is usually the biggest contributor to total execution time. The data used by Polars is stored in the Apache Arrow columnar format. This means that instead of storing the information one row at a time, Arrow stores each column as a group. This enables analytical operations to work with neighboring blocks of memory much more efficiently. It also allows for zero-copy interoperability with many other data-processing libraries. In AI applications that involve feature engineering and preprocessing, this can greatly cut down execution time.

性能不仅仅取决于 CPU 速度。我们还需要考虑在内存中移动数据所需的时间，这通常是总执行时间的最大占比。Polars 使用的数据存储在 Apache Arrow 列式格式中。这意味着 Arrow 不是按行存储信息，而是将每一列作为一个组进行存储。这使得分析操作能够更高效地处理相邻的内存块。它还允许与许多其他数据处理库进行零拷贝互操作。在涉及特征工程和预处理的 AI 应用中，这可以极大地缩短执行时间。

### The question now is: Is Faster Always Better?
### 现在的问题是：越快越好吗？

Short answer: “not necessarily”. Pandas is still one of the most powerful and widely supported libraries within the Python ecosystem. A large number of tutorials, visualization libraries, and machine learning frameworks make the assumption that you are using Pandas. Pandas is still a very good option for many projects, particularly for those working with small datasets. Polars begins to shine when you start working with datasets that become large, transformations become complex, parallel execution matters, or preprocessing becomes a bottleneck. Pandas is generally more than enough for exploratory notebooks, teaching, and smaller projects.

简短的回答是：“不一定”。Pandas 仍然是 Python 生态系统中最强大且支持最广泛的库之一。大量的教程、可视化库和机器学习框架都默认你正在使用 Pandas。对于许多项目，尤其是处理小型数据集的项目，Pandas 仍然是一个非常好的选择。当数据集变得庞大、转换变得复杂、并行执行变得重要，或者预处理成为瓶颈时，Polars 的优势才会显现出来。对于探索性笔记本、教学和小型项目，Pandas 通常绰绰有余。

Choosing between Pandas and Polars is not an either-or choice. It is still essential to understand Pandas since much of the Python data ecosystem relies on it. Studying Polars will, however, prepare you for the next generation of data processing.
在 Pandas 和 Polars 之间做选择并非非此即彼。理解 Pandas 仍然至关重要，因为大部分 Python 数据生态系统都依赖于它。然而，学习 Polars 将为你迎接下一代数据处理做好准备。
