# Building Multimodal Workflows with a Local LLM
# 使用本地大模型构建多模态工作流

**LLM Applications: Building Multimodal Workflows with a Local LLM**
**大模型应用：使用本地大模型构建多模态工作流**

Image inputs and structured outputs with Gemma 4 and Ollama
通过 Gemma 4 和 Ollama 实现图像输入与结构化输出

Running an LLM locally is attractive when working with private data or building workflows that should run on our own machine. And those workflows no longer need to be limited to text. In this post, we’ll build such a workflow with Gemma 4 and Ollama. We’ll place Gemma 4’s multimodal capability inside a larger process, where downstream steps can consume its structured output.
在处理隐私数据或构建需要在本地机器上运行的工作流时，在本地运行大模型（LLM）极具吸引力。而且，这些工作流不再局限于文本。在本文中，我们将使用 Gemma 4 和 Ollama 构建这样一个工作流。我们将把 Gemma 4 的多模态能力置于一个更大的流程中，使下游步骤能够使用其结构化输出。

I recently took a trip to Finland, and I took quite some photos during my journey. In this post, I’ll show you how I use the workflow to analyze them, and then show how the same workflow can power a small application.
我最近去芬兰旅行，途中拍了不少照片。在本文中，我将向大家展示如何利用该工作流来分析这些照片，并演示同一工作流如何驱动一个小应用程序。

### 1. The Multimodal Workflow
### 1. 多模态工作流

There are two ideas associated with the term “multimodal workflow”. First, multimodal. This means instead of working only with text, the LLM also receives inputs of other types, such as images. In this post, we consider the local LLM of Gemma 4 family from Google. This model family is capable of processing both image and text.
“多模态工作流”这一术语包含两个概念。首先是“多模态”。这意味着大模型不仅处理文本，还能接收其他类型的输入，例如图像。在本文中，我们考虑使用谷歌的 Gemma 4 系列本地大模型。该系列模型具备处理图像和文本的能力。

Then, workflow. This means instead of deciding autonomously what to do next as in an agentic loop, the LLM operates inside a pre-defined sequence, where each stage receives an input and produces an output for the next stage. LLM serves as a function that performs semantic transformations.
其次是“工作流”。这意味着大模型不再像智能体循环（agentic loop）那样自主决定下一步做什么，而是在预定义的序列中运行，每个阶段接收输入并为下一阶段产生输出。大模型在此充当执行语义转换的函数。

For our case study, we want to turn a folder of trip photos into organized memory records. To achieve that, we need to analyze each photo and translate its content into a consistent, structured record. Once those records are available, we can combine them to understand the entire collection. This naturally gives us a three-stage workflow:
在我们的案例研究中，我们希望将一个旅行照片文件夹转化为有组织的记忆记录。为此，我们需要分析每张照片，并将其内容转化为一致的、结构化的记录。一旦获得这些记录，我们就可以将它们组合起来，以理解整个照片集。这自然形成了一个三阶段的工作流：

```python
photos = prepare_photos("Finland_trip")
photo_memories = [
    analyze_photo(
        image=photo.image,
        metadata=photo.metadata,
    ) for photo in photos
]
trip_memory = synthesize_trip(photo_memories)
```

First, Python prepares the individual images and extracts useful metadata such as their capture times and GPS coordinates. Then, our local LLM Gemma 4 can analyze each photo and return a structured record of the visual content of the photo. Finally, we pass the individual records again to Gemma 4 to produce a structured summary of the entire collection. In what follows, we build the individual stages.
首先，Python 准备单张图像并提取有用的元数据，例如拍摄时间和 GPS 坐标。然后，我们的本地大模型 Gemma 4 分析每张照片，并返回照片视觉内容的结构化记录。最后，我们将这些单条记录再次传给 Gemma 4，以生成整个照片集的结构化摘要。接下来，我们将构建各个阶段。

### 2. Building the Workflow with Gemma 4
### 2. 使用 Gemma 4 构建工作流

#### 2.1 Running Gemma 4 Locally
#### 2.1 在本地运行 Gemma 4

First things first, we need to make Gemma 4 available locally. For that, we use Ollama, which gives us a local runtime and interface for interacting with the model. In this post, we use the E4B variant of Gemma, which is one of the edge-friendly models in the family.
首先，我们需要在本地部署 Gemma 4。为此，我们使用 Ollama，它为我们提供了与模型交互的本地运行时和接口。在本文中，我们使用 Gemma 的 E4B 版本，它是该系列中适合边缘计算的模型之一。

On Windows and macOS, you can download and run the installer from the Ollama website. On Linux, you can install from the terminal: `curl -fsSL https://ollama.com/install.sh | sh`
在 Windows 和 macOS 上，您可以从 Ollama 官网下载并运行安装程序。在 Linux 上，可以通过终端安装：`curl -fsSL https://ollama.com/install.sh | sh`

Once Ollama is installed, we can pull the Gemma model: `ollama pull gemma4:e4b`
安装 Ollama 后，我们可以拉取 Gemma 模型：`ollama pull gemma4:e4b`

We also need to install the Python packages needed for the workflow: `pip install ollama pillow pydantic`
我们还需要安装工作流所需的 Python 包：`pip install ollama pillow pydantic`

Here, `ollama` is needed for connecting our Python code to the local LLM, `pillow` handles the image processing, and `pydantic` is for structured output.
其中，`ollama` 用于将我们的 Python 代码连接到本地大模型，`pillow` 用于处理图像，`pydantic` 用于实现结构化输出。

#### 2.2 From Photo to Structured Record
#### 2.2 从照片到结构化记录

For each photo, we want to produce a structured record describing what the model sees. Before the images reach Gemma 4, we need to preprocess them. In our workflow, we implemented deterministic logic to resize the image and extract available EXIF metadata, and we wrap them inside `prepare_photo()`.
对于每张照片，我们希望生成一份描述模型所见内容的结构化记录。在图像进入 Gemma 4 之前，我们需要对其进行预处理。在我们的工作流中，我们实现了确定性逻辑来调整图像大小并提取可用的 EXIF 元数据，并将它们封装在 `prepare_photo()` 函数中。

From the workflow’s perspective, we only need its outputs:
从工作流的角度来看，我们只需要它的输出：

```python
from pathlib import Path
image, metadata = prepare_photo(Path("Finland_trip/photo.jpg"))
```

Here, `image` contains the prepared image bytes, while `metadata` is a dictionary containing the information extracted from the file. You can find the full implementation details in the repo attached in the end of the post.
这里，`image` 包含准备好的图像字节，而 `metadata` 是一个包含从文件中提取信息的字典。您可以在文末附带的仓库中找到完整的实现细节。

Next, we define the structured record we want Gemma 4 to return:
接下来，我们定义希望 Gemma 4 返回的结构化记录：

```python
from pydantic import BaseModel, Field

class PhotoMemoryAnalysis(BaseModel):
    scene_summary: str
    memory_caption: str
    place_type: str
    visible_activities: list[str]
    visible_objects: list[str]
    inferred_interest_signals: list[str]
    mood: str
    uncertainty_notes: list[str]
    confidence: float = Field(ge=0, le=1)
```

This is what we call structured output. Effectively, we pre-define this schema and ask the LLM to output according to this shape. This way, downstream code can access the result through typed attributes or convert it into a dictionary with `model_dump()`.
这就是所谓的结构化输出。实际上，我们预定义了这个模式（schema），并要求大模型按照这种格式输出。这样，下游代码可以通过类型化属性访问结果，或者使用 `model_dump()` 将其转换为字典。

Then, we build the instruction and prompt:
然后，我们构建指令和提示词：

```python
import json

PHOTO_ANALYSIS_INSTRUCTION = """
Analyze the supplied travel photo and its metadata. Return a structured record grounded in the provided inputs.
"""

def build_photo_prompt(metadata: dict) -> str:
    return f"""Photo metadata: {json.dumps(metadata, indent=2)} """
```

Now we can put everything together:
现在我们可以将所有内容整合在一起：

```python
import ollama

MODEL = "gemma4:e4b"

def analyze_photo(image: bytes, metadata: dict) -> PhotoMemoryAnalysis:
    response = ollama.chat(
        model=MODEL,
        messages=[
            {"role": "system", "content": PHOTO_ANALYSIS_INSTRUCTION},
            {"role": "user", "content": build_photo_prompt(metadata), "images": [image]},
        ],
        format=PhotoMemoryAnalysis.model_json_schema(),
        options={"temperature": 0},
    )
    return PhotoMemoryAnalysis.model_validate_json(response.message.content)
```

Note that we used `images` field to supply the visual input, and used `format` to ask Ollama to follow the defined schema. We can then parse the response into a regular Python object:
请注意，我们使用了 `images` 字段来提供视觉输入，并使用 `format` 参数要求 Ollama 遵循定义的模式。然后，我们可以将响应解析为常规的 Python 对象：

```python
photo_analysis = analyze_photo(image=image, metadata=metadata)
```

This way, we have the routine to transform a photo into one structured memory record.
通过这种方式，我们就拥有了将照片转换为结构化记忆记录的例程。
