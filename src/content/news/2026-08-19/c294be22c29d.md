# Ten Is Not a Hundred / 十不是一百

**Large Language Models: The number that fooled every hallucination detector**
**大语言模型：那个欺骗了所有幻觉检测器的数字**

Javier Marin | Aug 18, 2026 | 11 min read
Javier Marin | 2026年8月18日 | 11分钟阅读

### The problem / 问题所在

A bank runs a RAG system behind its customer-service chat. A user asks about an invoice. The retrieved document says the total due is 10,000 dollars. The chatbot tells the client that the total is 1,000 dollars. If you review it (and you are not an LLM), you see the problem in a second, and you don’t need a finance degree.
一家银行在其客户服务聊天机器人背后运行着一套 RAG（检索增强生成）系统。一位用户询问发票相关事宜。检索到的文档显示应付总额为 10,000 美元。而聊天机器人却告诉客户总额是 1,000 美元。如果你去核对（且你不是一个大语言模型），你一秒钟就能发现问题，而且根本不需要金融学位。

The bank has a review pipeline for exactly this. It uses rules and an LLM judge. The judge breaks the answer into statements and asks itself whether each one follows from the context. It measures meaning. And in the space where meaning lives, “the total is 1,000 dollars” and “the total is 10,000 dollars” are almost the same sentence.
银行专门为此设置了审核流程，使用规则和 LLM 裁判进行判断。裁判将答案拆解为多个陈述，并自问每一项是否都符合上下文。它衡量的是“语义”。而在语义存在的空间里，“总额是 1,000 美元”和“总额是 10,000 美元”几乎是同一个句子。

I spent a week measuring how the standard hallucination tools available today handle this problem. Then I spent a second week on the question underneath that one: whether any of them work at the operating point a production system actually runs at. The short version of the second week is that the answer is no. Not the trained detectors, not the LLM judge, not the entailment models, and not the thing I built either. I will show you the whole grid, including the cells where I lose.
我花了一周时间评估目前市面上的标准幻觉检测工具如何处理这个问题。随后，我又花了一周时间研究更深层的问题：在生产系统的实际运行环境下，这些工具是否有效？第二周的结论简而言之就是：无效。无论是训练过的检测器、LLM 裁判、蕴含模型，还是我自己构建的工具，都无法解决。我将向你展示完整的测试矩阵，包括我失败的部分。

### Hands on / 实操

I used RAGTruth [1], a public corpus of real RAG answers, and built a simple set: one hundred long, grounded responses (responses that match what the source document says), and for each one a copy with exactly the same answer but one number changed to a value that appears nowhere in the source document. A digit swapped, added or removed — 1,000 where the document says 10,000 or 35 where it says 53. The same error as above, two hundred times.
我使用了 RAGTruth [1]（一个公开的真实 RAG 答案语料库）并构建了一个简单的测试集：包含 100 个长篇且有据可查的回复（与源文档内容一致），并为每一个回复制作了一个副本，其中仅修改了一个数字，使其变为源文档中不存在的值。比如数字被替换、增加或删除——文档说 10,000，这里写 1,000；或者文档说 53，这里写 35。重复上述错误，共计 200 次。

I used five families of detectors, each one with a different approach:
我使用了五类检测器，每类都有不同的方法：

1. **Ragas-style LLM judge [2][3][4]**: The statement-decomposition pattern behind most “faithfulness” scores today.
   **Ragas 风格的 LLM 裁判 [2][3][4]**：目前大多数“忠实度”评分背后的陈述拆解模式。
2. **Embedding similarity**: With a frozen sentence encoder, aggregated by the mean.
   **嵌入相似度**：使用冻结的句子编码器，通过平均值聚合。
3. **BERTScore’s recipe**: Pointed at the retrieved context [5].
   **BERTScore 方法**：指向检索到的上下文 [5]。
4. **An entailment model**: A DeBERTa cross-encoder trained on natural language inference [6].
   **蕴含模型**：在自然语言推理上训练的 DeBERTa 交叉编码器 [6]。
5. **LettuceDetect [7]**: A span detector fine-tuned on thousands of labelled hallucinations, and the published state of the art at this size.
   **LettuceDetect [7]**：在数千个标注幻觉上微调的片段检测器，也是该规模下已发表的最先进模型。
6. **MiniCheck [8][9]**: The strongest small trained fact-checker I know of.
   **MiniCheck [8][9]**：我所知的最强小型训练事实核查器。

### The results / 结果

The results were close to unanimous.
结果几乎是一致的。

* **Ragas-style LLM judge**: AUROC=0.57
* **Embedding similarity**: AUROC=0.51
* **Entailment model**: AUROC=0.59
* **LettuceDetect**: AUROC=0.58
* **MiniCheck**: AUROC=0.75

Four of five detectors did not see the problem. Only MiniCheck showed a modest signal. Why do they miss it? Because all of them are answering a different question.
五分之四的检测器没有发现问题。只有 MiniCheck 显示出微弱的信号。为什么它们会漏掉？因为它们回答的根本是另一个问题。

### Embedding methods average the error away / 嵌入方法通过平均化掩盖了错误

Existing methods mainly compress the answer into a vector and measure its distance to the context. A sixty-word answer wrong in one digit produces a vector almost identical to the correct answer’s. If we measure for example cosine similarity, we get a value around 0.99. But the answer from the model is wrong. The error dissolves the way a drop of ink dissolves in a pool.
现有方法主要是将答案压缩成向量，并测量其与上下文的距离。一个 60 个词的答案如果错了一个数字，生成的向量与正确答案几乎完全相同。如果我们测量余弦相似度，会得到约 0.99 的值。但模型的答案是错的。错误就像一滴墨水滴入池塘一样消散了。

Sentence encoders are trained with an objective that collapses paraphrase (two ways of saying the same thing must land in the same place). That objective is what makes retrieval work, and magnitude is the first thing it discards. Encoders organise text by vocabulary, topic and structure. Never by truth.
句子编码器的训练目标是合并释义（表达相同意思的两种方式必须落在同一个位置）。这个目标使得检索有效，但“数值大小”是它首先丢弃的东西。编码器按词汇、主题和结构组织文本，从不按事实。

The LLM judge has a different failure. The model doing the checking has the same blind spot as the model that made the mistake: it reads for plausibility. “The total is 1,000 dollars” is a perfectly plausible sentence about an invoice. Nothing in the prompt forces it to compare digits.
LLM 裁判的失败原因则不同。负责检查的模型与犯错的模型有同样的盲点：它阅读是为了判断“合理性”。“总额是 1,000 美元”对于发票来说是一个完全合理的句子。提示词中没有任何内容强制它去比对数字。

The trained detector fails because its training distribution decides what it can see. It learned the hallucinations its annotators labelled, and single-digit numeric substitutions are rare in those labels.
训练过的检测器失败是因为其训练分布决定了它能看到什么。它学习的是标注员标记的幻觉，而单数字替换在这些标签中非常罕见。

### The oldest idea in computing / 计算领域最古老的想法

The fix for the problem we are discussing could be the oldest idea in computing. When we manually check an answer against a document, we do not summarise both and compare summaries. We take each piece of the answer and look for it. “The invoice” — there. “A total” — there. “1,000” is not in the document. The document says 10,000. The comparison happens at the resolution of the error.
解决我们讨论的问题的方法，可能是计算领域最古老的想法。当我们手动对照文档检查答案时，我们不会总结两者并比较摘要。我们取答案的每一部分去寻找。 “发票”——找到了。“总额”——找到了。“1,000”——文档里没有。文档说的是 10,000。比对发生在错误的颗粒度上。

Word against word, so the wrong token is never averaged with its neighbours. And we are using two different tests for two kinds of content. For words, “where is this?” is a question about meaning. For numbers it is arithmetic: 1,000 either equals a value in the document or it does not. We don’t evaluate the similarity of the numbers. 1,010 is no more acceptable than 10,000: both are wrong.
词对词比对，所以错误的标记永远不会与其邻居被平均化。我们对两种内容使用两种不同的测试。对于单词，“它在哪里？”是一个关于语义的问题。对于数字，它是算术问题：1,000 要么等于文档中的某个值，要么不等于。我们不评估数字的相似度。1,010 和 10,000 一样不可接受：它们都是错的。

Token-similarity metrics aggregate by the mean, and the mean is precisely where single-token errors go to die. So the answer-level figure here is the floor: the weakest anchor, or the mean of the few weakest. I packaged this as a small open-source library, **groundlens**. No training, no labels, no API call — one forward pass of a frozen encoder you already have, plus a regular expression. About seventy milliseconds per answer on a CPU.
标记相似度指标通过平均值聚合，而平均值恰恰是单标记错误消失的地方。因此，这里的答案级指标是“底线”：即最弱的锚点，或最弱的几个锚点的平均值。我将其打包成了一个小型开源库：**groundlens**。无需训练、无需标签、无需 API 调用——只需你现有的冻结编码器进行一次前向传播，再加上一个正则表达式。在 CPU 上，每个答案的处理时间约为 70 毫秒。
