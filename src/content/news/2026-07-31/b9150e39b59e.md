# How to Organize All of Your Coding Agent Tasks
# 如何管理你所有的编程智能体任务

In this article I’ve discussed how to organize all of the tasks you’re completing with your coding agents. Now that we have coding agents essentially performing all the coding implementations, another issue I’ve noticed is keeping track of all my tasks, which coding agent is interacting with my task, and so on. Task management has become a challenge in itself because we’re doing so many tasks at once.
在本文中，我将探讨如何组织你通过编程智能体（Coding Agents）完成的所有任务。现在，编程智能体基本上承担了所有的代码实现工作，我注意到的另一个问题是：如何跟踪我所有的任务，以及哪个智能体正在处理哪个任务等等。任务管理本身已经成为一项挑战，因为我们同时处理的任务实在太多了。

There is a challenge keeping track of everything. Of course, this is quite a good problem to have because we’re essentially saying that we’re doing so much work that it’s hard to keep track of everything, but as with anything else within engineering, we need to discover bottlenecks and resolve them so that we can unlock increased productivity.
跟踪所有事项确实存在挑战。当然，这是一个“幸福的烦恼”，因为这意味着我们的工作量巨大，以至于难以面面俱到。但正如工程领域的任何问题一样，我们需要发现瓶颈并解决它们，从而释放更高的生产力。

### Why task organization is harder now with coding agents
### 为什么有了编程智能体后，任务组织变得更难了

The simple fact is that with coding agents now, we’re just performing way more work as programmers. Previously these tasks listed below could take a whole day (or several days) in themselves: Implementing a design, Resolving a complex bug, Implementing a new feature. These are now tasks that you work on in parallel and complete in a maximum of one day.
简单的事实是，有了编程智能体，我们作为程序员的工作量大大增加了。以前，下面列出的任务可能需要一整天（甚至几天）才能完成：实现一个设计、解决一个复杂的 Bug、实现一个新功能。而现在，这些任务你可以并行处理，并且最多一天就能完成。

This is, of course, in stark contrast to before LLMs, i.e., before the release of ChatGPT in December 2022, where you would have to work on one task at a time; of course, you would have to do them sequentially, and each individual task would also take a lot longer to work on, for several reasons.
这与大模型（LLM）出现之前——即 2022 年 12 月 ChatGPT 发布之前——形成了鲜明对比。那时你必须一次处理一个任务；当然，你必须按顺序执行，而且由于各种原因，每个单独的任务都需要花费更长的时间。

All of these are essentially non-challenges now, because: The coding agents rarely create silly bugs anymore. They’ve basically been eliminated through writing code with AI coding agents and reviewing it with AI coding agents. You don’t need to learn new frameworks anymore because the coding agents either know them from before if they’re very established frameworks, or they can go online, research the frameworks, and understand them that way.
所有这些在现在基本上都不是问题了，因为：编程智能体很少再制造低级 Bug。通过使用 AI 智能体编写代码并由 AI 智能体进行审查，这些问题基本已被消除。你也不再需要学习新的框架，因为如果是非常成熟的框架，智能体要么预先就知道，要么它们可以上网研究这些框架并理解它们。

### How I do task management with coding agents
### 我是如何利用编程智能体进行任务管理的

In general, I want to highlight the following points: You need to ensure your coding agent task management system is connected to your coding agent through an API or an MCP. You should not be interacting with the system manually yourself, writing comments, updating on progress, and so on. That’s simply a waste of time, and you should make sure your coding agent does that automatically for you.
总的来说，我想强调以下几点：你需要确保你的编程智能体任务管理系统通过 API 或 MCP 与你的智能体连接。你不应该手动与系统交互、编写评论或更新进度等。那纯粹是浪费时间，你应该确保你的编程智能体能自动为你完成这些工作。

You should make sure to work in separate worktrees when you do your work. If not, you’ll have issues with coding agents overlapping. There are numerous ways to work with separate worktrees. Claude Code has a separate flag you can use for it and many other coding agent interfaces such as Emdash handle it automatically for you.
在工作时，你应该确保在独立的工作树（worktrees）中进行。否则，你会遇到编程智能体相互干扰的问题。有很多方法可以处理独立的工作树。Claude Code 有一个专门的标志位可以使用，而许多其他编程智能体界面（如 Emdash）会自动为你处理。

Basically, whenever I receive a new task, I’ll immediately spin up a new worktree session in my Emdash application or new workspace, and start working on the task. I’ll also make sure that I rename the worktree something unique and appropriate so that I can know exactly what work is being done there just by the worktree name without having to read any logs within the coding agent.
基本上，每当我收到一个新任务时，我都会立即在我的 Emdash 应用程序或新工作区中启动一个新的工作树会话，并开始处理该任务。我还会确保将工作树重命名为一个独特且恰当的名称，这样我只需通过工作树名称就能确切知道那里正在进行什么工作，而无需阅读智能体内的任何日志。
