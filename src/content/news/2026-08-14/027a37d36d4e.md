# Self-Evolving Code-with-Image Reasoning
## 自我演进的“代码辅助图像推理”

Multimodal models increasingly reach for tools when solving visual tasks (crop, zoom, rotate, brighten), a paradigm known as thinking-with-images. The central challenge is one of perception: tools mostly serve to expose visual evidence, reasoning over that evidence stays in language, and most targets are ones a human could in principle determine by inspection.

多模态模型在解决视觉任务时越来越多地借助工具（如裁剪、缩放、旋转、提亮），这种范式被称为“图像辅助思考”（thinking-with-images）。其核心挑战在于感知：工具主要用于呈现视觉证据，而对这些证据的推理仍停留在语言层面，且大多数目标在原则上是人类通过观察就能确定的。

Some visual questions, however, are not bottlenecked by perception: recovering their answers requires executing a multi-step visual algorithm over the pixels. On such questions a model often names the correct algorithm at once yet still answers wrong, because language can describe an algorithm without being able to run one.

然而，有些视觉问题并不受限于感知：要得出答案，需要对像素执行多步视觉算法。在处理这类问题时，模型往往能立即说出正确的算法，但回答依然错误，因为语言可以描述算法，却无法运行算法。

Code-with-Image crosses that line: given nothing but a Python interpreter, the model must implement a genuine visual algorithm in code to solve the task; the program itself becomes the reasoning. The bottleneck then shifts from executing code to deciding which algorithm to implement.

“代码辅助图像推理”（Code-with-Image）跨越了这一界限：模型仅配备一个 Python 解释器，必须通过代码实现真正的视觉算法来解决任务；程序本身即是推理过程。此时，瓶颈从“执行代码”转移到了“决定实现哪种算法”。

So we let the model teach itself: a training-free reflection loop studies its own failed programs, tests repairs against constructive ground truth, and keeps what survives as portable skills.

因此，我们让模型进行自我教学：一个无需训练的反射循环（reflection loop）会研究其失败的程序，根据建设性的真值（ground truth）测试修复方案，并将存活下来的方案保留为可移植的技能。

On our Code-with-Image Bench (CwI-Bench), thirty task families induced by hidden visual computations with disjoint learning and evaluation splits, even GPT-5.6-luna stays below 30% with tool-free chain of thought; given a bare interpreter it reaches 43%, and with skills evolved through its own executable reflection, 67%. The open 27B model climbs the same ladder (9% $\rightarrow$ 33% $\rightarrow$ 56%), and the skills are plain text, transferable across scales and families. When code carries the reasoning, debugging code becomes debugging reasoning.

在我们的 Code-with-Image 基准测试（CwI-Bench）中，包含三十个由隐藏视觉计算诱导的任务族，并设有独立的学习和评估集。即使是 GPT-5.6-luna，在使用无工具的思维链时准确率也低于 30%；在配备基础解释器后达到 43%；而通过其自身可执行反射演进出的技能，准确率提升至 67%。开源的 27B 模型也遵循同样的提升路径（9% $\rightarrow$ 33% $\rightarrow$ 56%），且这些技能以纯文本形式存在，可在不同规模和任务族之间迁移。当代码承载推理时，调试代码就等同于调试推理过程。
