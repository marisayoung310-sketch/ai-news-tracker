# How to Perform Effective Project Management with AI
# 如何利用人工智能进行有效的项目管理

Project management has changed a lot now in the time of LLMs. It’s essentially completely changed how the field works and how you effectively develop a good product and complete work on engineering tasks. In this article, I’ll discuss how to perform effective project management in the age of AI, both from the perspective of orchestrating tasks and deciding what can be done, and then how to effectively work with the tasks themselves to complete them as efficiently as possible.

在大型语言模型（LLM）时代，项目管理已经发生了巨大的变化。它从根本上改变了该领域的工作方式，以及你如何高效地开发优质产品并完成工程任务。在本文中，我将探讨如何在人工智能时代进行有效的项目管理，包括如何编排任务、决定工作优先级，以及如何高效地处理任务以实现最高的工作效率。

### Why project management has changed
### 为什么项目管理发生了变化

The main reason project management has changed in the era of LLMs is that the time we spend on various tasks in project management while working on a tech project has changed radically. Well, previously, the distribution of time spent for a software engineer could be something like this: 70% – Write code, 15% – Meetings, 15% – Testing.

LLM 时代项目管理发生变化的主要原因在于，我们在科技项目中处理各类管理任务的时间分配已经发生了根本性的改变。此前，一名软件工程师的时间分配大致如下：70% 用于编写代码，15% 用于会议，15% 用于测试。

The time spent coding has now essentially become 0, since I don’t write any code myself. I do, however, spend time prompting agents, which would be a sort of replacement: 30% – Prompt agents, 10% – Meetings (keeping this the same), 30% – Testing (much more time is spent testing), 30% – Time extra that I can spend on other stuff.

现在，编写代码的时间几乎降为零，因为我不再亲自写代码了。取而代之的是，我将时间花在向智能体（Agents）发送提示词上：30% 用于提示智能体，10% 用于会议（保持不变），30% 用于测试（测试时间大幅增加），30% 用于处理其他事务的额外时间。

### Map out work more beforehand
### 事前做好更充分的任务规划

The first thing I spend more time on now than I did previously is mapping out work beforehand. My tasks usually come from a Slack message (product feedback/bug), or from a project I’m working on. When I start working on those tasks, I try to map out the work as much as possible beforehand. The reason you should spend more time on this now is that having work mapped out allows you to have agents run for longer periods of time fully autonomously, i.e., you don’t have to interact with them as often.

我现在比以往投入更多时间的第一件事，就是事前做好任务规划。我的任务通常来自 Slack 消息（产品反馈/漏洞报告）或我正在进行的项目。当我开始处理这些任务时，我会尽量提前做好详尽的规划。现在之所以要在这方面投入更多时间，是因为清晰的任务规划能让智能体在更长的时间内完全自主运行，也就是说，你不需要频繁地与它们进行交互。

### Use the /goal command
### 使用 /goal 命令

The second important point of project management that I do is to actively use the /goal command. This ties closely into the last task that I mentioned about mapping out work beforehand. And this tip will not be effective if you don’t map out the task properly beforehand. The /goal command is essentially a hook that the agent triggers every time the agent says that it completed the work, and it makes the agent reflect on whether it actually completed all the work you requested from it or not.

我进行项目管理的第二个要点是积极使用 `/goal` 命令。这与我刚才提到的事前规划密切相关。如果你没有提前做好任务规划，这个技巧将无法发挥作用。`/goal` 命令本质上是一个钩子（hook），每当智能体声称完成工作时，它就会触发该命令，促使智能体反思是否真正完成了你所要求的所有工作。
